# Proposal

## Why

The OpenSpec provider declares the `spec-driven` schema SUPPORTED, but it cannot read a change written with the
`spec-driven` templates of the OpenSpec CLI it targets. Measured on 2026-10-08 at `3ec3ea46`: reading this
repository's own `openspec/` (initialised with OpenSpec CLI 1.14.1, one change written from its templates) leaves
CHANGES, REQUIREMENT_DELTAS, CONSTRAINTS, DESIGN_DECISIONS and IMPLEMENTATION_TASKS `FAILED` with "OpenSpec proposal
has no Proposal title", while the probe still answers SUPPORTED. The same audit reproduced two input-handling
defects on the M0 fixture: a requirement duplicated in a delta makes `read()` throw instead of reporting `FAILED`,
and a UTF-8 BOM at the start of `config.yaml` or `spec.md` is reported as a missing schema or a missing title
(findings PRV-AUD-1, PRV-AUD-2, PRV-AUD-3 in `docs/audits/AUDIT_OUTILLE_2026-10-08.md`).

## What Changes

- The provider reads proposals written with the upstream `spec-driven` template (`# Proposal`, `## Why`,
  `## What Changes`, `## Capabilities`, `## Impact`) in addition to the M0 dialect (`# Proposal: <title>`,
  `## Intent`), or the probe stops claiming SUPPORTED for workspaces it cannot read — decision recorded in design.md.
- One malformed change no longer fails every change-derived category: the failure is attributed to the change and
  its file.
- A duplicated requirement or scenario in a delta is reported as an invalid source attributed to its file; `read()`
  never throws for content it reads.
- A leading UTF-8 BOM is accepted in every file the provider reads; a quoted `schema:` scalar is accepted.
- Current-specification sections stop at the next level-two heading and ignore headings inside code fences, as the
  delta reader already does.

## Capabilities

### New Capabilities

- `openspec-provider-reading`: which OpenSpec workspace layouts and document dialects the provider reads, how it
  reports content it cannot read, and how failures are attributed.

### Modified Capabilities

(none — `openspec/specs/` holds no capability yet)

## Impact

- `morpheus-provider-openspec`: `OpenSpecChangeMetadataReader`, `OpenSpecRequirementDeltaReader`,
  `OpenSpecCurrentSpecificationReader`, `OpenSpecSpecificationContentReader`, `OpenSpecSpecificationProvider`.
- `morpheus-application`: `SafeWorkspaceFileResolver` if BOM stripping is done at decoding.
- Fixtures: a new fixture generated by the OpenSpec CLI (`experiments/m0/fixtures/openspec-upstream-*`).
- ADR-0028 (provider read contract): amendment naming the supported dialects.
